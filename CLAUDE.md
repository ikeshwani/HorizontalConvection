This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`TopographicHorizontalConvection` is a Julia package for simulating 2D/3D ocean horizontal convection with bottom topography. It is built on [Oceananigans.jl](https://github.com/CliMA/Oceananigans.jl) and targets GPU-accelerated runs on the NCSA Delta HPC cluster.

The physical setup: a non-uniform buoyancy is imposed at the top surface of a fluid domain, driving thermohaline circulation. Bottom topography (Gaussian hills) is represented via an immersed boundary.

## Environment Setup

First-time setup — instantiate all dependencies from the project root:

```bash
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

`LocalPreferences.toml` (gitignored) pins the CUDA runtime version (`CUDA_Runtime_jll` v13.0.2) for the Delta cluster. Do not commit it; it is machine-specific.

## Running Simulations

All Julia scripts must be run **from the `scripts/` directory** with the project root as the Julia project:

```bash
cd scripts/
julia --project=../ job_scripts/run_3hill_GRC.jl
```

Cluster jobs are submitted via SLURM (scripts live in `scripts/job_scripts/`):
```bash
sbatch scripts/job_scripts/submit_thc.sh    # flat-bottom control
sbatch scripts/job_scripts/submit_hill.sh   # hill simulation
```

Long simulations run in numbered **segments**. Each segment script sets `segment=N` and calls `run!(simulation, pickup=true)` to resume from the checkpoint saved at the end of the previous segment. The checkpoint file is named `<prefix>_checkpoint.jld2` inside the output grid directory. The checkpoint is written every 1.0 nondimensional time unit (`TimeInterval(1.0)`).

The checkpoint filename prefix is generated by `generate_filename()` in `src/simulation.jl` and encodes run parameters (e.g. `turbulent_flat_0.0_Ra1e8_zerostart`).

## Core Architecture

### Module structure (`src/`)

- **`simulation.jl`** — all simulation construction logic (the only file most users touch)
- **`analysis.jl`** — volume integral utilities (`global_volume_integral`, `global_volume_avg`) for 2D NetCDF post-processing
- **`RANS_energies.jl`** — Reynolds-averaged energy budget diagnostics
- **`grid_testing.jl`** — grid spacing inspection utilities
- **`SIM_GPU_TEST.jl`** — GPU benchmarking/validation
- **`simulation_test.jl`** — alternate simulation variant (currently commented out of `TopographicHorizontalConvection.jl`)

### Main entry point

`HorizontalConvectionSimulation(; kwargs...)` in `src/simulation.jl` constructs and returns an Oceananigans `Simulation`. Key keyword arguments:

| Category | Parameters |
|---|---|
| Domain | `Nx`, `Ny`, `Nz`, `H`, `α` (aspect ratio Lx/H), `x_stretch`, `z_stretch`, `stop_time` |
| Topography | `numhill` (0–3), `h₀_frac` (hill height as fraction of H) |
| Physics | `Ra`, `Pr`, `b★`, `advection`, `b_init` |
| Forcing | `winter_amplitude`, `summer_amplitude`, `seasonal_period` |
| Coriolis | `coriolis`, `coriolis_scheme` (`:fplane` or `:betaplane`), `latitude_south`, `latitude_north`, `coriolis_reference_latitude` |
| Wind | `wind`, `wind_stress`, `wind_spatial_profile`, `use_SO_westerlies`, `SO_westerlies_magnitude`, `SO_westerlies_center_lat`, `SO_westerlies_width` |
| Output | `output_dir`, `segment`, `output_writer` |
| Compute | `architecture` (`CPU()` or `GPU()`) |

### Key design decisions

- **2D vs 3D**: `Ny=1` triggers 2D mode (`Seafloor2D`, `surface_buoyancy_2d`). `Ny>1` is 3D with periodic y. In 3D, `Ly = Lx / (Nx ÷ Ny)`.
- **Pressure solver**: Flat bottom (`numhill=0`) uses the default FFT-based solver. Any hills use `ConjugateGradientPoissonSolver` because the immersed boundary breaks the FFT assumption.
- **GPU safety**: Seafloor heights are pre-computed on CPU then transferred (`CuArray`) to avoid closure captures on the GPU. All seafloor and buoyancy structs are `isbits`.
- **Grid stretching**: `x_stretch` is the ratio Δx_max/Δx_min and refines toward the left x boundary (x = -Lx/2). `z_stretch` similarly refines toward the top z boundary (z = 0, ocean surface). `stretch=1.0` gives a uniform grid.
- **Nondimensionalization**: `ν = sqrt(Pr * b★ * H³ / Ra)`, `κ = ν/Pr`. Equilibration timescale is `τ_eq = sqrt(Ra)`.
- **Advection**: `advection=true` uses `WENO()` with CFL=0.5; `advection=false` uses `Centered(order=2)` with CFL=Inf (no adaptive timestep).
- **3D hill geometry**: Hills are Gaussian with `hill_length = Lx/32`; in 3D a y-direction channel modulation uses `channel_width = Ly/8`. Relative heights scale as 1.0 / 0.75 / 0.5 for hills 1/2/3.

### Output structure

Outputs are written to `output_dir/<Nx>_<Nz>/` with filenames like:
- `buoyancy_seg$(N).nc` — `b`, tracer variance dissipation `chi` (χ), buoyancy flux `ϕz`; every **0.1** time units
- `velocities_seg$(N).nc` — `u`, `v`, `w`; every **0.1** time units
- `section_snapshots_seg$(N).nc` — 2D midplane slice of `b`, KE, PE; every **10** time units
- `oceanostics_seg$(N).nc` — KE, dissipation rate ε, χ (midplane slice); every **5** time units
- `zonal_time_means_seg$(N).nc` — y-averaged buoyancy; window-averaged over 1 unit every **10** time units
- `*_checkpoint.jld2` — Oceananigans checkpoint for segment pickup; every **1.0** time units

**NetCDF coordinate naming**: Cell-centered coordinates are `x_caa`, `y_aca`, `z_aac`; cell spacings are `Δx_caa`, `Δy_aca`, `Δz_aac`. Global attributes include `Nx`, `Ny`, `Nz`, `Lx`, `Ly`, `H`, `Ra`, `Pr`, `b★`.

**Wet mask pattern**: Immersed (dry) cells have `b=0` at `t=0` (same as initial condition), so always compute the wet mask from the second time step: `wet = Array(b[:, :, :, 2]) .!= 0`.

## Analysis Scripts

All analysis scripts are in `scripts/analysis_scripts/` and run from `scripts/` with `julia --project=../`. **All scripts hardcode absolute paths and configurable parameters at the top — edit these before running.**

### Computation

| Script | Purpose |
|---|---|
| `segment_files.jl` | Inspects segment files and trims overlapping time steps |
| `combine_and_save_segments.jl` | Appends segment NetCDFs onto a `combined_t<T>.nc` file |
| `G_mix_calc.jl` | G_mix via buoyancy-mask binning method (older, slower) |
| `G_mix_sort.jl` | G_mix via sorting method for **control** (flat bottom); faster than mask method |
| `G_mix_sort_hill.jl` | G_mix via sorting method for **hill** experiments |
| `psi_of_b.jl` | Streamfunction in buoyancy coordinates ψ(b,t) |
| `psi_of_b_sort.jl` | ψ(b,t) via sorting method for control |
| `psi_of_b_sort_hill.jl` | ψ(b,t) via sorting method for hill experiments |
| `psi_b_region_flux.jl` | ψ(b,t) plus regional G_mix flux diagnostics |
| `chi_eps_region_stats.jl` | Regional statistics of χ and ε (above/below/near hills) |
| `BPEcalc.jl` | Background potential energy (BPE) diagnostics |
| `energy_fluxes.jl` | Energy flux terms |
| `kinetic_energetics.jl` | Kinetic energy budget terms |
| `gmix_to_density.jl` | Convert G_mix output to density coordinates |

### Plotting / Animation

| Script | Purpose |
|---|---|
| `figuresGRC.jl` | Main GRC figures for hill experiment (configurable at top: `experiment`, `Ra_str`, `seg_range`, etc.) |
| `figuresGRC_Control.jl` | GRC figures for control (flat bottom) experiment |
| `plot_surf_buoy.jl` | Plot surface buoyancy evolution |

| `animate_hilly_horizontal_convection.jl` | Animation script for hill runs |

### SLURM submission scripts

Job-submission scripts in `scripts/job_scripts/`: `submit_thc.sh` (control), `submit_hill.sh` (hill).

Analysis-submission scripts in `scripts/analysis_scripts/`: `submit_gmix_control.sh`, `submit_gmix_hill.sh`, `submit_psi_b_control.sh`, `submit_psi_b_hill.sh`, `submit_psi_b_region_flux.sh`, `submit_chi_eps_region_stats.sh`, `submit_figuresGRC.sh`, `submit_figuresGRC_Control.sh`, `submit_animations.sh`.

## Cluster Configuration

- **GPU jobs**: partition `gpuA40x4`, account `bfxn-delta-gpu`, 1 GPU + 4 CPUs
- **CPU jobs**: partition `cpu`, account `bfxn-delta-cpu`
- **Typical resources**: 36–140 GB RAM, up to 48-hour wall time
- Simulation output paths follow the pattern: `/work/hdd/bfxn/ikeshwani/HorizontalConvection/output/GPU/<experiment>/<Ra>/<stretch>/<Nx>_<Nz>/`
- The SLURM `--signal=USR1@120` flag gives the simulation 120 s of graceful shutdown time to write a checkpoint before the job is killed.
